为了将【文言心】从设计哲学落地为真实的编译器/解释器，我们需要将之前的规则进行**工程化拆解**，定义清晰的内部数据结构、边界情况处理机制以及编译管道。

以下是面向后期开发的详细展开规范。

### 一、 词法分析 工程：无空格分词的严格算法

前期我们确立了“类型切换即分词”，但在真实世界中，我们会遇到字符串、多字变量名等。需要确立优先级机制。

**1. 字符分类与优先级**
*   `META`：结构锚点（`。` `，` `'` `'` `『` `』`），最高优先级，遇到立刻切断上下文。
*   `NUM`：数字（`0-9` `.`），支持浮点数。
*   `HAN`：基本汉字（CJK Unified Ideographs），动词/标识符。
*   `SPACE`：空白符，仅作同类数据（NUM与NUM）的分隔符，直接丢弃。

**2. 多字动词贪心匹配**
词法分析器需要持有一个**字典**。当遇到连续汉字时，优先查字典匹配最长的关键字，而不是逐字切分。
*   例如：遇到 `定义阶乘`，字典中有 `定义`，则切分为 `[定义, 阶乘]`。
*   如果没有多字关键字，才退化为单字切分：`皆乘` $\to$ `[皆, 乘]`。

**3. 字符串与注释的逃逸**
*   引入 `"..."` 用于包含空格的字符串字面量：`"Hello World"`。
*   引入 `注：` 或 `--` 开启单行注释，直接在 Lexer 阶段丢弃。

### 二、 语法分析 工程：AST 节点与吞噬优先级

我们需要定义 AST 的基本节点结构，以及动词吞噬的优先级，防止歧义。

**1. 核心 AST 节点定义**
```python
class Node: pass

class Num(Node):       # 数字字面量
    value: float | int

class Word(Node):      # 动词/标识符
    name: str

class Call(Node):      # 函数调用
    verb: Node         # 通常是 Word
    args: List[Node]   # 参数列表

class Pipeline(Node):  # 管道结构 (由，生成)
    steps: List[Node]  # 按顺序执行的步骤列表

class Quote(Node):     # 引用结构 (由 `'expr` 生成)
    expr: Node         # 未求值的 AST 节点
```

**2. 吞噬优先级**
当 Parser 从左向右读取 Token 流时，遵循以下优先级构建 Call 节点：
1.  **副词修饰**：`皆`、`只` 等副词，优先吞噬右侧的 `Call` 节点作为其高阶参数。
2.  **动词吞噬**：普通动词向右吞噬 `Num` 或 `Quote`。
3.  **管道切断**：遇到 `，`，立刻结束当前 Call 的吞噬，将当前 Call 压入 Pipeline 的 steps 中。

**示例推演：`列1 2 3，皆乘2。`**
1.  读到 `列`，创建 `Call(verb=列, args=[])`。
2.  读到 `1 2 3`，吞噬入 args，得到 `Call(列, [1, 2, 3])`。
3.  读到 `，`，切断！将 `Call(列)` 压入 Pipeline。
4.  读到 `皆`，创建 `Call(皆, [])`。
5.  读到 `乘`，创建 `Call(乘, [])`。
6.  读到 `2`，被 `乘` 吞噬，得到 `Call(乘, [2])`。
7.  **副词修饰**：`皆` 发现右侧是 `Call(乘)`，吞噬之，得到 `Call(皆, [Call(乘, [2])])`。
8.  读到 `。`，将 `Call(皆)` 压入 Pipeline，结束。

### 三、 语义层 工程：元数、柯里化与管道注入

这是【文言心】最精妙也最容易出 bug 的地方，必须严格数学化定义。

**1. 元数声明**
环境字典不仅存储函数实现，还必须存储该函数期望的**参数总数**。
```python
Env = {
    "加": (2, lambda a, b: a + b),
    "列": (-1, lambda *args: list(args)), # -1 代表可变参数
    "皆": (2, map_func),
}
```

**2. 严格柯里化规则**
当动词吞噬的参数数量 `len(args)` < 元数 `arity` 时：
*   **右侧参数先占位**：将已有的 `args` 绑定到函数的右侧参数位。
*   **返回闭包**：生成一个 `lambda left_arg: func(left_arg, *args)`，并标记该闭包的剩余元数为 `arity - len(args)`。

**3. 管道注入规则**
当执行 `Pipeline(steps)` 时，维护一个隐式的 `pipeline_value`。
对于 `steps` 中的每一个 `Call` 节点：
1.  若 `pipeline_value` 为空，正常求值当前 `Call`，将结果赋给 `pipeline_value`。
2.  若 `pipeline_value` 非空，将其注入当前 `Call`：
    *   如果当前 `Call` 的动词是一个**闭包（缺参）**，将 `pipeline_value` 作为左操作数传入闭包执行。
    *   如果当前 `Call` 的动词是**可变参数（如列）**，将 `pipeline_value` 追加到参数列表末尾（或首位，需特殊约定）。
    *   如果当前 `Call` 的动词**参数已满**，抛出语义错误（管道溢出）。

### 四、 同像性 工程：引用与宏

实现 Lisp 级别的同像性，必须让程序能操作 AST。

**1. Quote 机制 (`'expr`)**
在 Parser 阶段，遇到 `'`，开启引用模式，读取后续表达式作为 AST，不求值。内部的 Token 构建成 AST，但**不挂载到当前的 Call 树上**，而是作为一个 `Quote` 节点存在。
在 Evaluator 阶段，遇到 `Quote` 节点，**直接返回其内部的 AST 数据结构**，不求值。

**2. Eval 机制 (`行`)**
提供内置动词 `行`，它接收一个 AST 数据结构（即 Quote 的结果），强制将其注入当前环境求值。
*   `行 '1加2`。` $\to$ 对 AST `Call(加, [1, 2])` 求值，得到 3。

**3. 宏机制**
有了 Quote 和 AST 操作，就可以实现宏。例如，实现一个 `交换` 宏，传入一个二元操作 AST，返回一个参数反转的新 AST。
（这部分属于高阶扩展，V1.0 可暂不实现，但架构上必须保留操作 AST 的能力）。

### 五、 标准环境设计

为了让语言可用，需要预置一套精简、符合中文直觉的动词库。

| 类别 | 动词 | 元数 | 语义说明 |
| :--- | :--- | :--- | :--- |
| **数据构造** | `列` | -1 | 构建列表：`列1 2 3。` |
| | `典` | -1 | 构建字典：`典『名』张三 『龄』25。` |
| **算术** | `加` `减` `乘` `除` `模` | 2 | 基础算术 |
| **比较** | `大` `小` `等` | 2 | 返回 真/空 |
| **逻辑** | `且` `或` `非` | 2/1 | 逻辑运算 |
| **高阶操作** | `皆` | 2 | 遍历映射：`皆乘2。` |
| | `只` | 2 | 过滤保留：`只大5。` |
| | `归` | 2 | 归约折叠：`归加0。` (求和) |
| **存取** | `首` | 1 | 取首元素 |
| | `余` | 1 | 取余下列表 |
| | `入` | 2 | 索引取值：`入2。` (取第三个) |
| **I/O与控制** | `印` | 1 | 打印输出 |
| | `若...则...否则` | 3 | 条件分支 |
| | `定` | 2 | 变量/函数绑定 |

### 六、 编译管道架构

为了后期开发，建议采用 Python 或 Rust 实现，整体架构分为四步：

```text
[源代码字符串] 
    ↓ (1. Lexer: 无空格分词, 贪心匹配)
[Token 流: Word, Num, Punct...]
    ↓ (2. Parser: 动宾吞噬, 副词修饰, 管道构建)
[AST: Pipeline(Call, Call...)]
    ↓ (3. Macro Expand: 处理 Quote 与宏) [V2.0]
[AST]
    ↓ (4. Evaluator: 柯里化, 管道注入, 求值)
[结果数据]
```

**开发里程碑建议：**
*   **MVP (v0.1)**：实现 Lexer (单字切分) + Parser (动宾吞噬) + Evaluator (仅算术与管道)。能跑通 `10加5，乘2。`。
*   **v0.2**：引入列表 `列` 与高阶函数 `皆` `只`，实现柯里化。能跑通 `列1 2 3皆乘2。`。
*   **v0.3**：完善 Lexer 的多字贪心切分，引入条件判断 `若` 与变量定义 `定`。实现阶乘递归。
*   **v0.4**：引入同像性，实现 `'expr` Quote 与 `行` Eval，允许程序操作自身 AST。

这份展开规范已经足以作为一份严谨的工程 Task Breakdown，可以直接依此进行模块化编码了。
