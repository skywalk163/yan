# ANTLR 版本言语言实现总结

## 已完成的工作

### 1. 完整的 ANTLR 实现

**文件结构：**
```
yan/antlr/
├── Yan.g4                  # ANTLR 语法文件
├── generated/              # 生成的解析器文件
│   ├── YanLexer.py        # 词法分析器
│   ├── YanParser.py       # 语法分析器
│   └── YanVisitor.py      # 访问者基类
├── ast_builder.py          # AST 构建器
├── codegen.py              # 代码生成器
├── main.py                 # 主入口
├── test.py                 # 测试脚本
├── README.md               # 使用文档
└── ANTLR_SUMMARY.md        # 总结文档
```

### 2. 核心功能实现

**词法分析：**
- 关键字：若、则、否则、定、函、真、假、空、遍历、于、当、等于
- 内置动词：印、加、减、乘、除、模、幂、绝对、负、大、小、等、不等、且、或、非、首、余、入、长、连、含、皆、只、归
- 操作符：=、。、；、，、：、'
- 数学表达式：$(...)
- Python 代码块：{{...}}
- 字符串："..."
- 数字：整数和小数
- 标识符：汉字序列或拉丁字母

**语法分析：**
- 程序和语句
- 定义语句（三种形式）
- Lambda 表达式
- 代码块
- 条件表达式
- 循环（遍历、当）
- 函数调用
- 原子值

**AST 构建：**
- 将 ANTLR 解析树转换为言语言 AST 节点
- 处理动词和标识符连写的情况（如"印张三"）
- 处理"定"关键字和标识符连写的情况（如"定张三"）

**代码生成：**
- 将 AST 转换为 Python 代码
- 支持所有语法结构
- 正确处理多行语句和缩进

### 3. 关键技术决策

**动词识别：**
- 词法分析器使用最长匹配原则，将"印张三"识别为一个标识符
- 在 AST 构建器中拆分动词和参数
- 支持动词列表：印、加、减、乘、除、模、幂、绝对、负、大、小、等、不等、且、或、非、首、余、入、长、连、含、皆、只、归

**"定"关键字处理：**
- 词法分析器将"定张三"识别为一个标识符
- 在 AST 构建器中拆分"定"和变量名
- 支持三种定义形式：定 名称 = 值、名称 = 值、名称 等于 值

**运行时环境：**
- 使用 Python 的 `exec()` 函数执行生成的代码
- 添加内置函数到运行时环境
- 使用 `builtins.compile()` 编译 Python 代码

## 与手写解析器的对比

| 指标 | 手写解析器 | ANTLR 解析器 |
|------|-----------|-------------|
| 代码行数 | ~800 行 | ~150 行 (语法文件) + ~300 行 (AST/代码生成) |
| 错误处理 | 基础 | 强大（精确的错误位置） |
| 可维护性 | 中等 | 高 |
| 工具支持 | 无 | 丰富 |
| 学习曲线 | 陡峭 | 平缓 |
| 调试难度 | 高 | 低 |

## 已知问题和限制

1. **"等于"定义形式**
   - "王五等于30" 被解析为函数调用，而不是定义语句
   - 需要在语法层面处理

2. **动词列表**
   - 当前硬编码在 AST 构建器中
   - 应该从 runtime.py 自动提取

3. **错误处理**
   - 需要自定义错误监听器
   - 提供更友好的错误信息

## 使用方法

```bash
# 安装依赖
pip install antlr4-python3-runtime antlr4-tools

# 生成解析器
cd yan/antlr
java -jar antlr-4.13.1-complete.jar -Dlanguage=Python3 -visitor -no-listener -o generated Yan.g4

# 运行测试
python test.py

# 运行代码
python main.py examples/hanoi_full.yan
```

## 结论

ANTLR 版本提供了更清晰、更易维护、更强大的解析器实现。虽然需要学习 ANTLR 语法，但长期来看，ANTLR 的优势远大于学习成本。建议将 ANTLR 版本作为言语言的官方解析器实现。
