# 言语言架构设计文档

---

## 一、项目概述

**言语言（Yán）** 是一门以中文为语法核心的函数式编程语言，转译到 Python 执行。本文档描述了言语言编译器/解释器的完整架构设计。

## 三、核心模块详细设计

### 3.1 词法分析器 (Lexer)

#### 3.1.1 架构职责

- 将中文源代码字符串转换为结构化的 Token 流
- 支持无空格分词（贪心匹配字典）
- 处理字符串字面量、注释、数学表达式、Python 代码块

#### 3.1.2 Token 类型

| Token 类型 | 说明 | 示例 |
|-----------|------|------|
| `WORD` | 中文动词/标识符 | 加、乘、定义、列 |
| `NUM` | 数字字面量 | 123、3.14 |
| `STR` | 字符串字面量 | "Hello" |
| `PUNCT` | 标点符号 | 。、；：（） |
| `MATH` | 数学表达式 | $(1 + 2) |
| `PYTHON` | Python 代码块 | {{x = 1}} |

#### 3.1.3 分词算法

```
1. 读取字符流
2. 根据字符类型切换状态（META/NUM/HAN/SPACE）
3. 遇到 META 字符立即切断上下文
4. 连续汉字使用贪心匹配字典进行分词
5. 空白符仅作同类数据分隔符，直接丢弃
```

### 3.2 语法分析器 (Parser)

#### 3.2.1 架构职责

- 将 Token 流转换为抽象语法树（AST）
- 处理动词吞噬、副词修饰、管道构建
- 支持块结构、条件语句、函数定义

#### 3.2.2 AST 节点类型

| 节点类型 | 说明 | 结构 |
|---------|------|------|
| `Num` | 数字字面量 | `value: float | int` |
| `Str` | 字符串字面量 | `value: str` |
| `Word` | 动词/标识符 | `name: str` |
| `Call` | 函数调用 | `verb: Node, args: List[Node]` |
| `Pipeline` | 管道结构 | `steps: List[Node]` |
| `Define` | 定义语句 | `name: str, value: Node` |
| `Lambda` | 匿名函数 | `params: List[str], body: Node` |
| `If` | 条件语句 | `cond: Node, then: Node, else: Node` |
| `Block` | 代码块 | `statements: List[Node]` |

#### 3.2.3 动词吞噬优先级

1. **副词修饰**：`皆`、`只` 等副词优先吞噬右侧的 `Call` 节点
2. **动词吞噬**：普通动词向右吞噬 `Num` 或 `Quote`
3. **管道切断**：遇到 `，` 结束当前 Call 的吞噬

### 3.3 优化器 (Optimizer)

#### 3.3.1 架构职责

- 对 AST 进行优化变换
- 支持多种优化级别和策略
- 提供优化统计和诊断信息

#### 3.3.2 优化策略

| 策略 | 文件 | 功能 |
|------|------|------|
| `ConstantFolding` | `constant_folding.py` | 编译时常量表达式求值 |
| `DeadCodeElimination` | `dead_code_elimination.py` | 移除不可达代码 |
| `ExpressionSimplification` | `expression_simplification.py` | 简化布尔表达式 |
| `TailRecursionOptimization` | `tail_recursion_optimization.py` | 尾递归检测和优化 |

#### 3.3.3 优化级别

| 级别 | 名称 | 启用的优化 |
|------|------|-----------|
| `O0` | 无优化 | 无 |
| `O1` | 基础优化 | 常量折叠、死代码消除、表达式简化 |
| `O2` | 完全优化 | 所有优化 + 尾递归优化 |
| `Os` | 空间优化 | 优化代码大小 |
| `Ofast` | 快速优化 | 所有优化（牺牲正确性换取速度） |

### 3.4 代码生成器 (CodeGen)

#### 3.4.1 架构职责

- 将优化后的 AST 转换为 Python 代码
- 处理柯里化、管道注入、高阶函数
- 支持尾递归优化的循环转换

#### 3.4.2 代码生成流程

```
AST → 遍历节点 → 生成对应 Python 代码 → 处理特殊语法（柯里化、管道）→ 输出完整代码
```

### 3.5 模块系统 (ModuleSystem)

#### 3.5.1 架构职责

- 模块加载和缓存
- 导入导出语法支持
- 循环依赖处理（延迟加载）
- 热更新支持

#### 3.5.2 核心功能

| 功能 | 说明 |
|------|------|
| **版本管理** | 从 package.json 提取版本信息 |
| **依赖解析** | 构建依赖图，验证版本约束 |
| **循环依赖** | 使用延迟加载机制处理 |
| **热更新** | 监控文件变化，自动重新加载 |

### 3.6 调试器 (Debugger)

#### 3.6.1 架构职责

- 断点设置和管理
- 步进执行控制
- 变量监视和求值
- 调用栈查看

#### 3.6.2 调试状态

| 状态 | 说明 |
|------|------|
| `STOPPED` | 调试已停止 |
| `RUNNING` | 程序正在运行 |
| `PAUSED` | 程序暂停（断点/手动暂停） |
| `STEPPING` | 步进执行中 |

## 四、数据流与控制流

### 4.1 编译流程

```
源代码字符串
    │
    ▼ (Lexer.tokenize)
Token 流
    │
    ▼ (Parser.parse)
AST
    │
    ▼ (ASTOptimizer.optimize)
优化后的 AST
    │
    ▼ (CodeGen.generate)
Python 代码
    │
    ▼ (exec/eval)
执行结果
```

### 4.2 管道操作的处理

```
源代码: 10加5，乘2，减3。
           │
           ▼
Pipeline(steps=[
    Call(verb=加, args=[10, 5]),
    Call(verb=乘, args=[2]),
    Call(verb=减, args=[3])
])
           │
           ▼
执行过程:
  step 1: 10 + 5 = 15
  step 2: 15 * 2 = 30
  step 3: 30 - 3 = 27
           │
           ▼
结果: 27
```

## 五、关键设计决策

### 5.1 双轨制语法设计

**决策**：采用中文语法为主，同时支持 `$()` 数学表达式和 `{{}}` Python 代码块

**理由**：
- 中文语法符合自然语言直觉，降低学习门槛
- 数学表达式使用熟悉的数学符号
- 直接嵌入 Python 代码可利用丰富的 Python 生态

### 5.2 动词吞噬机制

**决策**：动词根据参数数量自动收集参数

**理由**：
- 符合中文语言习惯（动词在前，宾语在后）
- 简化语法，无需显式括号
- 支持可变参数函数

### 5.3 管道操作符

**决策**：使用 `，`（中文逗号）作为管道操作符

**理由**：
- 逗号在中文中表示停顿，语义上适合表示数据流动
- 无需引入新的语法符号
- 支持链式操作

### 5.4 模块系统设计

**决策**：实现延迟加载处理循环依赖

**理由**：
- 循环依赖在实际项目中难以避免
- 延迟加载允许模块在使用时才完整加载
- 提供清晰的错误提示

class CustomOptimization(OptimizationStrategy):

        return node
