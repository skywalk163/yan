# 错误处理集成计划

## 目标

将 `error.py` 模块的高级错误处理功能集成到编译器中，提供友好的错误信息。

## 当前状态

### 已实现
- ✅ `error.py` 模块：完善的错误类（YanError, LexerError, ParserError等）
- ✅ 源代码片段显示
- ✅ 错误建议系统（ErrorSuggester）
- ✅ 友好的错误格式化

### 待集成
- ❌ `lexer.py` 使用简单的 LexerError 类
- ❌ `parser.py` 使用简单的 ParserError 类
- ❌ 未使用源代码片段和建议功能

## 集成步骤

### 阶段1：迁移词法分析器错误处理
1. 修改 `lexer.py` 导入 `error.py` 模块
2. 替换 LexerError 类为 `error.LexerError`
3. 在错误抛出时传递源代码和建议

### 阶段2：迁移语法分析器错误处理
1. 修改 `parser.py` 导入 `error.py` 模块
2. 替换 ParserError 类为 `error.ParserError`
3. 在错误抛出时传递源代码和建议

### 阶段3：增强错误建议
1. 扩展 `ErrorSuggester.COMMON_ERRORS` 字典
2. 添加更多常见错误的建议
3. 实现智能拼写检查

### 阶段4：测试验证
1. 编写错误处理测试用例
2. 验证错误信息格式
3. 验证建议准确性

## 预期效果

### 改进前
```
词法错误 (行3, 列5): 字符串未闭合
```

### 改进后
```
词法错误: 字符串未闭合
  位置: test.yan:3:5

    1 | 定x=1。
    2 | 定y="hello
  > 3 | 印y。
        ~~~~~^
    4 | 

  提示: 字符串需要用双引号包裹，例如："hello"
```

## 实施优先级

**高优先级**：
1. 阶段1：词法分析器集成
2. 阶段2：语法分析器集成

**中优先级**：
3. 阶段3：增强错误建议
4. 阶段4：测试验证

## 风险评估

- **兼容性**：需要确保现有代码不受影响
- **性能**：错误处理不应影响正常编译速度
- **测试**：需要全面测试错误场景
